## Try the game

In Garden Home choose **Add Crux**, then **Zen of Vibecoding**, then **Create**. The new project is your own fresh game. Read its first mission and choose **Check my garden** to see what the mission expects. Reading the missions does not require AI. The game checks real files and Tasks; it is not a simulated completion animation.

To use a real agent, open **Settings → AI**, enable **AI Tools**, and configure your provider or agent. Your provider may charge for its work. Never paste a key into the project or conversation. Without AI, you can still read the lessons and experiment with files and Tasks yourself.

## Start with one small Task

Choose an independent change: “Draft a shorter introduction” is easier to review than “Improve everything”. A Task keeps its work and conversation associated with that assignment.

The **Crux Garden: The Zen of Vibecoding** instructional game is a hands-on way to practice, from one Task to several collaborating agents. Real agents require configured providers and may incur provider charges.

1. Open **Panels → Tasks** (or search **Tasks** with ⌘K/Ctrl+K).
2. Choose **New task**, give it a specific name, and choose **Save and start task**. You are now in that Task's copy of the project.
3. With AI enabled, open **Collaboration** in that Task and send its assignment. Creating a Task alone does not ask an agent to work.
4. Return to **Main** in the Tasks list while it works. The Task's state and progress tell you whether it is working or needs attention.
5. Open the Task when it needs you. Answer its question or review the approval before work can continue.

## Follow the feedback

Task status tells you whether work is running, waiting for your attention, finished, or failed. Progress is the agent’s best estimate, not a stopwatch or a promise. Read the latest progress message when a percentage stops changing.

If an agent asks for approval or clarification, inspect the request in its Task. Closing or switching a panel is not the same as cancelling the work.

## Review what comes back

Open the Task’s report and inspect its changed files or result. A completion message does not prove the change is correct. Preview it, compare it with your intent, and run relevant checks before merging work back.

Make a named Growth version before accepting a substantial change.

When a Task is ready, open it and choose **Review changes**. Inspect the proposed changes and verification result before merging into Main. Return to Main and preview the result. A Task that says it is finished still needs your review.

## Add parallel work deliberately

Give agents separate responsibilities and explicit destinations. A good pair is “write the introduction” and “check the navigation”. Two agents rewriting the same file require more coordination.

When a result is missing, check the Task’s owner and status before starting a duplicate. See [Troubleshooting](../../reference/troubleshooting/).
