# miniPaint inside Crux Garden

Source: https://github.com/viliusle/miniPaint
Version: 4.14.3, commit a79733eb803fc97084ef0ee4faa96b031e69e1c0.

The original editor, actions, effects, layered JSON and raster exporters are retained. Garden adds a save/reload bar, captures the native document and stores raster pixels separately. Native JSON export reconstructs inline pixels from the editor as usual. App source and rebuildable runtime accompany each Crux.

Changes: Garden startup/bridge, scoped layer agent operations, runtime output directory, native document validation. The envelope lives in data/project.json and raster references in data/assets. Current bounds: 500 layers, 8192 pixels per side and 32 megapixels per canvas/raster layer. This is not a large-document performance guarantee.

Native image imports retain the editor's decoded pixels in lossless PNG form, not the original camera file or all original EXIF metadata. External Google font discovery remains an upstream online feature; custom fonts are not currently packaged into the Crux. Use locally available fonts for offline projects. Native exports are available; whole-editor website/Explore distribution is not enabled by this integration.

The top-level code is MIT; retain MIT-LICENSE.txt, upstream helper notices in src/js/libs and dependency notices. Bundled third-party helpers and optional assets retain their own terms. A complete public distribution audit is separate work.

## Shared command lifecycle, 2026-09-14

`src/js/garden/bridge.js` adopts the common serialized settle → validate → confirm pending edits → native action → settle → confirm result lifecycle. Layer updates continue through miniPaint's native Bundle/Update actions and Undo. `garden/shared/command-session.{js,d.ts}` and `project-image.{js,d.ts}` are generated copies of Garden's canonical `embedded-apps/shared/` helpers, synchronized before the host build and included in the portable source. Standalone builds need no parent-repository files. Review the action/capture hooks and run manual/agent/Undo/restart/export checks on every upstream update.

## Editable banner workflow, 2026-09-14

The bridge uses existing Insert/Update/Delete/Reorder layer actions for text, filled rectangles, image imports, geometry, exact text revision and layer ordering. Canvas resizing uses the native Update-config and Prepare-canvas actions; optional layer scaling is one native Undo transaction. Text remains native styled spans; exact replacement preserves unrelated spans. The native hidden text input loses focus before an agent command so the person's pending edit enters native Undo. Pending actions are awaited and the native renderer is flushed before capture/output. No new changes to upstream action or editor files are needed for this depth extension.

The image helper reads a relative PNG/JPEG/WebP Artifact (or an existing native raster reference) from this Crux's preview origin, refuses traversal and redirects, and bounds input to 32 MB and decoded dimensions to the project limits. Images stay separate editable layers with original pixel dimensions; native PNG capture preserves their pixels. Layer text supports local font families and wrapping, not the full native typography/effects catalogue. Crop/expand retains off-canvas layer content. Font scaling on nonuniform canvas resizing uses the smaller ratio. This is not arbitrary SVG import, remote-image fetching, masking, or full upstream command parity. Live filtering was added in the subsequent painting family below.

Upgrade checks: native text-span format and blur commit; Insert-layer behavior when supplied a decoded `link`; Update-layer rendering invalidation; Reorder direction; Prepare-canvas ordering; native layered JSON/raster capture and export. The desktop banner journey must exercise agent creation, manual text revision, agent continuation, native Undo/Redo, PNG output, restart and clean portable import. Its verification status is tracked in the root Tool Depth plan.

## Painting and live photo adjustments, 2026-09-15

Five additional App Tools expose constant-width brush strokes, layer duplication, live filter add/update/remove, arbitrary in-canvas crop and native session Undo/Redo (fourteen tools total). `garden/editing.js` owns validation and pure native-data preparation. The bridge applies existing Insert/Update/Prepare-canvas actions; no additional upstream editor files are changed. Brush points become native editable brush-layer data, not a flattened replacement image. Each call creates one independently movable/deletable stroke layer. Pressure variation, brush-point revision, selections, erasing, fill and retouching remain future families.

Supported live filters are brightness, contrast, saturation, hue rotation, blur, grayscale, sepia and invert. Their native renderer retains original raster pixels. Filter IDs, parameters, order, available ranges and native history availability are inspectable. Filter updates/removal preserve unrelated filters and their order. Use `Update_layer_action` with a cloned filters array: the upstream `Add_layer_filter_action.undo()` pops the last filter even after an update, so that action cannot safely serve this command's update/history contract. This does not repair the upstream manual filter dialog's own update-Undo behavior; review that separately before promising full manual filter-history coverage.

Duplication copies native data, retains position and omits private caches. Imported images can retain a decoded element after their temporary blob URL has been released; cloning that URL fails to decode. The bridge copies the original-resolution decoded pixels to a fresh lossless PNG-backed image element and awaits decoding before insertion. Cropping translates every layer, including hidden layers, and changes canvas dimensions in one Undo transaction; it retains off-canvas content and performs no resampling. Commands refuse active drawing drafts or native dialogs and refuse intervening edits during the confirmed pre-save. The desktop journey must validate pixel changes in output, untouched source pixels, native and agent history, manual text preservation, restart and fresh portable import. Deterministic integration testing does not establish real-model visual judgment or professional photo-editing quality.

## Raster regions and native history, 2026-09-15

Three additional App Tools (seventeen total) set/clear native rectangular selection, erase a round stroke or selected rectangle, and fill connected color regions, matching pixels across a layer or the selection. Inspection reports active tool, transient selection and original raster dimensions. `garden/raster.js` validates and prepares original-resolution pixels; existing Select/Activate-tool/Set-selection/Reset-selection and Update-layer-image actions commit changes. No replacement editor or project rewrite. Rectangle boundaries round outward to original pixels; stroke size and coordinates follow canvas pixels, accounting for translation and unequal display scaling. Erasing/fill supports unrotated raster image layers; vector/rotated layers refuse. Live filters and other layers remain independent. Seed fills compare original RGBA before live filters, with explicit tolerance and source-over opacity. These hard-edged pixel operations do not claim feathering, masks, rotated-region editing or the entire upstream fill/retouching UI. Selections are native session state, not persistent project content. Seed fill/stroke deliberately ignore any active selection; selection mode explicitly uses it.

Native source repairs required by the shared workflow:

- `src/js/actions/add-layer-filter.js`: preserve the complete prior filter list on Undo, retain inserted identity across Redo, normalize native dialog IDs and refuse missing update IDs. Agent inspection/targeting also accepts older numeric-string filter IDs. The preceding manual-filter limitation is repaired by this family, subject to its recorded verification.
- `src/js/actions/update-layer-image.js`: snapshot a temporary canvas at action construction (native eraser/selection callers immediately reset it), retain decoded original pixels rather than a possibly revoked import URL, await decoding on do/Undo, and refuse an edit if its Undo pixels cannot be stored. Uses the existing native image store; synchronous PNG capture adds a cost on large images, not a large-document performance guarantee.
- `src/js/tools/selection.js`: use local scaled dimensions during Delete instead of overwriting the native selection rectangle; Undo must restore its original canvas-space geometry.

Keep these three narrow upstream fixes in the rebase checklist. Validate both native and agent history, an imported image with a released URL, manual Delete on a nonuniformly scaled selection, original Artifact preservation, transparent/isolated/global fills, outputs, restart and complete portable import. `garden/native-history.test.mjs` executes the actual action bodies with editor dependencies stubbed; the desktop raster journey exercises the actual UI and storage. Verification status and evidence are recorded in the root Tool Depth plan; these are not real-model or photo-quality acceptance tests.

## Raster conversion and compositing, 2026-09-15

Two more App Tools (nineteen total) rasterize an inspected native layer and merge selected/all visible layers. The existing layer-update tool now exposes the standard Canvas blend/composite modes; inspection reports the current mode and supported list. `garden/compositing.js` owns bounded planning and validation. Rasterization renders a visible copy through native `render_object`, baking geometry, rotation and filters while retaining the original layer's visibility, opacity, composition and stack position on the new raster. The target raster spans the current canvas: content outside it is deliberately clipped. Hidden layers can be converted without becoming visible. Text/shape editing data is replaced, with native Undo restoring it; duplicate first to retain an independent original.

Selected merges require adjacent visible, nonempty, source-over layers and refuse a following native clipping layer. This avoids silently breaking backdrop-dependent compositions. The visible mode uses miniPaint's complete native composite, bakes opacity/filters/blending into one normal raster at the highest replaced position, and retains hidden/empty layers separately. Revealing hidden layers afterwards interacts with the new flattened layer according to their retained order; it does not reconstruct their former interleaving with removed layers. Both modes clip outside the current canvas. Insert/Delete actions form one native Undo transaction; decoded PNG pixels are ready before insertion, and edits arriving during rendering/pre-save cause refusal. These are canvas-resolution rasterization tools, not resolution-independent export or editable layer groups/masks.

Additional narrow upstream repair: `src/js/actions/insert-layer.js` honors an explicitly supplied `is_vector` and uses `endsWith('.svg')` only when no classification was supplied. The old index comparison classified three-character names as SVG and could turn a known PNG into a vector solely from its label, blocking raster editing. Garden supplies explicit raster identity for decoded PNG imports/conversions. The actual native insertion action has a red/green regression including Undo/Redo; retain this in the rebase checklist. No other native layer/renderer modules are changed for this family.

Desktop acceptance must compare pixels before/after native text conversion, adjacent merge and a complete composition with rotation/live filtering/multiply/opacity; restore original editable layers through native Undo; retain hidden layers; preserve a person's native opacity edit through restart and complete portable import; then erase pixels on the resulting image. Current verification status is in the root Tool Depth plan. Broader blend combinations, masks, retouching, full typography and real-model/photo-quality acceptance are not inferred from this fixture.

## Inspection freshness and shared native transactions, 2026-09-15

The portable `garden/freshness.js` issues session-local state tokens from actual native layer data, image identity/source, selection, canvas dimensions, guides/fonts and native history identities/epochs. It excludes private render caches and viewport zoom; it does not PNG-encode images merely to inspect them. All editing/output tools accept `expectedState`. Once artwork exists, the native boundary requires the token from inspection or a successful previous result; the empty editor can be initialized without one. Reload creates a new session identity. Native Undo/Redo completion advances history state even when an unobserved pair returns the artwork to identical content. A stale/missing token refuses before the command mutates anything; inspect and review before retrying. This is explicit comparison, not automatic overwriting or silent retry.

The bridge blurs native editing fields before settling their history and checks both the supplied state and a preparation baseline. Direct property edits therefore enter native Undo before comparison. It refuses active pointer gestures/drawings/dialogs, and rechecks after import/copy/render decoding. During a native action/Undo transaction only, the editor workspace is inert and trusted native input is prevented from entering an asynchronous transaction; Collaboration outside the iframe remains available. The ordinary native controls become usable when the transaction ends, including on failure. No additional upstream file changes for this family. The host fingerprint acknowledgement and shared command queue continue to govern durable saves; session tokens do not replace those checks.

Token-bearing calls require a refreshed portable source/runtime in existing Cruxes. Helpers compare the native layer data in memory; very large projects still require separate performance acceptance. Current native tests and final app/desktop verification status are tracked in the root Tool Depth plan. Do not claim arbitrary native-gesture correctness solely from a stale-state test.

The action-observation wrapper must call the original action immediately, then observe its returned Promise. Deferring invocation through a Promise callback breaks native brush startup, which reads the inserted layer synchronously. The freshness desktop regression begins a real native brush stroke, attempts an agent command while held, then completes the stroke and checks its persisted point data. This is an adapter timing correction, with no brush-source fork.
