# Blockbench in Crux Garden

Native Blockbench web app, v5.1.6, upstream commit `794e964e966b6783b4e9b98ecbdda5152c0620cc` from https://github.com/JannisX11/blockbench. GPL-3.0-or-later; see LICENSE.MD. The Garden adaptation is distributed under the same license. Upstream branding, source and dependency notices are preserved. Models you create belong to you under upstream's stated policy.

Supported workflow: native modeling, texture painting, animation, BBModel import/export and embedded-media glTF export, with Garden saves, scoped agent edits and portable Crux export/import.

`npm ci --ignore-scripts && npm run build` rebuilds runtime with the pinned lockfile. The fork retains the native web editor, formats, modeling, painting and animation UI. Electron packaging is outside this web fork.

Garden stores the model library, individual native BBModel documents, embedded textures/audio and preferences as fingerprinted Artifacts. Closing a native tab retains the model in the library; use Reopen model to restore it. Native exports still produce ordinary files. Browser storage is an isolated runtime cache. Browser auto-backups, PWA installation, remote plugins, online sessions and URL-triggered imports are disabled. Undo and animation playback are transient. External URLs are not offline assets; import media locally for portability.

`npm run test:garden` checks component validation, native media/animation round trips, unchanged media reuse and isolated Storage behavior. The Garden host adds Growth/archive and command-validation tests. Its real desktop Playwright journey covers manual resizing and painting, moving animation keyframes, native exports/import, agent edits, conflicts, multiple model tabs, restart and complete Crux import with the original Project Folder unavailable.

Undo, playback position and global reference-image collections are not durable library state. Project-specific embedded reference images travel in their native model. Remote URLs remain external dependencies. Close or apply native dialogs before checkpointing. The supported library is bounded to 500 models and individual component assets to 64 MiB. Closing retains a model; the library currently offers reopening rather than a separate permanent-delete command. Growth preserves earlier states.

## Model-depth adapter (2026-09-14)

The Garden adapter exposes Generic Model creation, cube/group creation, exact cube geometry revision, hierarchy moves, empty-group/cube deletion and native naming. Geometry commands use the native `Cube`, `Group`, `Undo`, preview-controller and selection APIs. Naming uses native `saveName`; deletion records the post-deletion element list, and native group deletion retains animation bookkeeping. Texture painting and animation authoring remain native manual workflows. Generic Model geometry is the initial supported format; other native formats remain available manually.

Integration inventory: `garden/commands.js` is the shared host/frame validation contract; `garden/model-commands.js` adapts native operations; `garden/bridge.js` uses the common command session, confirmed saves and output controls; `garden/main.js` initializes the adapter after native startup and model restoration. `garden/shared/` is generated from the host-independent sources under `embedded-apps/shared/` using `node embedded-apps/sync-shared.mjs` in the host app. `garden/build.cjs` copies these integration files. This unit adds no patches to upstream editor source files.

Commands flush active native fields and wait for dialogs, texture loading and native Undo transactions to settle. They recheck active model identity and target-part state after the confirmed pre-save. IDs come from inspection of the active model. Inspection returns at most 50 parts per page; library, texture and animation summaries return their first 50 entries. Geometry commands allow 1,000 parts, bounded finite coordinates and positive cube dimensions. Moving retains stored geometry and pivot coordinates, so transformed parents can alter world appearance. Deleting a group requires moving/deleting its children first. Model creation and project naming follow native behavior without a geometry Undo step.

Outputs use the native BBModel codec with embedded media and the native glTF codec with ASCII encoding and embedded textures/buffers. glTF output rejects external asset URIs. Existing native export settings otherwise apply. Native Save model output and Save glTF output controls use the same lifecycle as agent exports. New runtime versions apply to newly created Cruxes; existing Project Folders are not silently upgraded.

Upgrade checks: run native model/command tests, host validation/packaging/output tests and both real desktop Blockbench journeys. Verify native geometry/group creation, scoped edits preserving manual names, UVs and texture pixels, structural and geometry Undo/Redo, usable embedded BBModel/glTF output, restart, complete Crux import with its original Project Folder unavailable, and further native editing. Recheck the signatures and Undo behavior of `Cube.init/addTo/remove`, `Group.init/remove`, `saveName`, `Canvas.updateView`, preview controllers, `newProject`, and both native codecs. Scripted integration evidence does not establish live-agent usability or complete texture/animation tool coverage.
