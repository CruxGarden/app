Self-contained resources are the supported import path; external resource dependencies are not automatically collected.

## Garden operations and Cruxspace outputs (2026-09-12)

`Garden/Project.js` answers bounded operations on the native gd API: `add-resource` (an image or audio file of this Crux, read through the new `read-file` bridge op, becomes a named resource), `add-sprite-object` (a Sprite object with one looping animation, optionally sliced from a sheet by frame size, with behaviors added through `WholeProjectRefactorer`), `add-instance`, `add-event` (one standard event from native condition/action types and string parameters) and `export-web-game` (the native HTML5 export pipeline, saved as a ZIP output of the Crux). The Export dialog gained “Save web game to Cruxspace”. The objects panel may not refresh until the scene is reopened after an agent operation; the saved document is complete. See `GAME-CRUXSPACE-PLAN.md` at the repository root.

## Native scene-instance editing (2026-09-15)

`garden/instances.mjs` validates whole batches and applies scoped native instance setters, duplication with new persistent UUIDs, deletion and insertion. `newIDE/app/src/Garden/SceneTools.js` binds these operations to the active native SceneEditor, its selection/renderer refresh and existing `Utils/History` serialization. `Garden/Project.js` supplies command preparation to the shared runner. The upstream SceneEditor touches are its adapter import, registration/unregistration in mount/unmount, and forwarding its existing `unsavedChanges` prop to EditorsDisplay. Desktop verification found that missing prop left manual compact property edits visible but unsaved; forwarding it restores the native dirty notification chain. Keep these four touches isolated when updating upstream; verify the binding against native editor/history method changes.

Fresh state tokens cover the current native project and editor/history identities. Preparation and post-save checks reject intervening edits; active native text/number editing must finish before scene commands run. A manual instance change absent from native history is captured before the tool's own step. Selection/inspection do not write the document. Deletion/history clear old native references and refresh renderers before returning; additions now use the same native history path. Native stored custom dimensions are distinct from rendered bounds.

This is scene-instance coverage, not event/object/resource/layer authoring completeness. The legacy object-list refresh limitation above remains for object definitions. ## Runtime JSX and crash-report boundary (2026-09-15)

The native runtime TSX uses its local DOM factory `h`; Garden's minimal root tsconfig omitted `jsxFactory`, causing esbuild to emit `React.createElement` into the 3D editor/debugger runtime, where React is absent. The root config now supplies `jsx: react` with `jsxFactory: h`. A native compiler/DOM regression renders and dismisses the debugger without any React global; desktop acceptance waits for the actual 3D toolbar and rejects captured page/debugger crashes. Earlier canvas-only assertions could finish before the 3D crash surfaced, so earlier 3D screenshots alone were insufficient evidence.

The existing Garden-adapted BrowserSWPreviewLauncher sets crash-report upload level to `none`. The reproduced runtime failure exposed attempts to upload to the upstream analytics endpoint (blocked by the isolated test); local previews must keep project crash details local. No runtime React dependency is added.

## Native object/behavior properties and animation timing (2026-09-15)

`garden/objects.mjs` exposes bounded native descriptor inspection and typed scalar/choice/color/existing-reference edits, plus existing Sprite animation timing/looping. Native setters validate the entire ordered batch on an owned `UniquePtrObject` clone (`clone.get()`; delete only the owner), then apply to the original object after the shared pre-save and fresh-state check. Boolean conversion follows PropertiesMapToSchema (`1`/`0`); dynamic descriptors are reread between updates. Specialized types remain explicitly non-writable. Native GetDirection aliases direction zero when multiple directions are disabled, so nonzero requests in that mode are refused.

`Garden/ObjectTools.js` reuses the SceneEditor registry/state guard exported from `Garden/SceneTools.js`; the existing Project adapter adds dispatch. No additional upstream component hook. Completion calls the same `_onObjectEdited` path as the native object dialog's Apply, preserving object identity and updating resource usage, renderers, shared behavior data and dirty state. Keep this callback contract and native descriptor semantics in the upstream upgrade checklist.

Native object dialogs offer Apply/Cancel; these settings are not part of SceneEditor's instance history. The tools state that explicitly and retain Garden Growth rather than inventing a second object Undo system. Native engine tests cover movement behavior values, whole-batch refusal, text-object settings/global scope, and animation preservation. Desktop acceptance must interleave manual behavior fields and guarded tool revisions, reopen the native form and repeat after clean import; current verification is recorded in the root assessment. Structural object/behavior operations, animation frame authoring, variables/events and atomic resource creation remain separate families.

## Native event authoring and history (2026-09-15, verified)

Four new scoped tools inspect event/instruction paths, organize nested events, revise native conditions/actions and use the event history. `garden/events.mjs` validates shape, metadata/parameter slots and all target paths on an owned native EventsList copy before mutating the real list. Native expression semantics and object references still require preview; metadata validity is not runtime correctness. Creation currently supports standard/comment/group events; existing event containers can be organized, with conditions/actions and nested subinstructions edited where native lists exist. Specialized loop/link/JavaScript configuration, event variables and while-guard lists remain separate authoring coverage.

`Garden/EventTools.js` adds a registry through an import and mount/unmount calls in the native EventsSheet component. Preserve these three narrow hook sites on upstream updates. It rechecks project/editor/history state after confirmed pre-save and after the selection-clearing render; native event history remains separate from scene-instance history. Drop selected/search references before deletion/history restoration, refresh the native tree and toolbar, mark search results dirty, and await the confirmed save. History entries include the native positions context so the person's Undo/Redo toolbar can consume them. The older add-event path remains distinct and does not gain this binding implicitly; migrate it deliberately with existing demo compatibility checks.
