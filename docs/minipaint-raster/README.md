# miniPaint raster regions and shared native history

Verified 2026-09-15. Three added App Tools bring miniPaint to seventeen: native rectangular selection; stroke/selection erasing; and contiguous/global/selection fill. Operations use original raster pixels with translated/nonuniformly scaled canvas coordinates and retain native live filters. Selection remains native session state. Supported targets are unrotated raster layers.

The isolated desktop journey `electron/e2e/minipaint-raster.spec.ts` passes in 46.7 seconds (47.1 including setup). It uses a synthetic 20×20 pixel image displayed at 400×200 inside a 600×360 canvas. This makes exact color boundaries, alpha and selection coordinates testable; it is not a photograph, artistic demo or real-model judgment test.

Thirteen tool calls over two normal Collaboration turns create the image, retain two live filters, select/fill a rectangle, erase a stroke, Undo/Redo that erasure, fill a connected area and fill matching pixels across the layer. Exact original-pixel samples verify all three fill modes, erasing and the unchanged dividing boundary/source Artifact. The native selection appears in the same editor for the person to continue through normal Delete. Native Undo restores both the entire prior PNG and the selection's unscaled canvas coordinates; Redo restores the person's deletion. Editing the first of two filters through its native dialog then passes Undo/Redo without losing the second filter or changing raster pixels.

The journey restarts, exports a complete Crux, takes its original Project Folder offline, imports into a fresh Garden and continues with nine calls. These exercise selection erasing, clear/Undo, half-opacity selection fill and one deliberate refusal to erase without a selection. The original Artifact and the person's erased region survive, as do the manually revised filters. The new PNG output is saved and native UI remains usable. No captured page errors. Half-opacity RGB comparison allows one level of canvas premultiplication rounding; alpha and opaque-pixel expectations remain exact.
