# Host UI usability and accessibility — October 1, 2026

This review exercises the actual Electron app with a disposable Garden. It covers the host interface, not the internal interfaces of every embedded third-party editor or user-created website. No personal Garden, account or saved manual-test score was changed.

## Findings and fixes

| Finding                                                                                  | Impact                                                                                                      | Resolution                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add Crux lets Shift+Tab leave its modal                                                  | Keyboard users reach obscured controls; background content remains available to assistive technology        | Shared `useModalFocus` owns tab wrapping, programmatic focus containment, background `inert`, stack ordering, cleanup and return focus. Used by Modal, command palette, workspace switcher and app-close prompt. |
| An import-error dialog opens over another modal                                          | The underlying dialog can intercept the new dialog's initial autofocus                                      | Preserve initial-focus intent on shared controls; the foreground focus owner honors it after background isolation. Escape dismisses one layer.                                                                   |
| Model chooser advertises a listbox but renders buttons                                   | Assistive technology receives the wrong interaction contract; keyboard focus and selected state are unclear | Named nonmodal chooser, pressed-state choices, selected-item initial focus, arrows/Home/End, Escape and return focus. Tab can leave normally.                                                                    |
| Shared Input/Textarea errors are only visual text                                        | A focused field does not expose its invalid state or explain the error                                      | `aria-invalid`, associated error description and alert; caller help descriptions are preserved.                                                                                                                  |
| Destructive confirmation initially focuses the destructive action                        | An accidental second Enter can confirm deletion                                                             | Cancel is the initial action; deletion remains an explicit choice.                                                                                                                                               |
| Keyboard-focused Undo expires after six seconds                                          | A keyboard user loses the focused recovery action                                                           | Hover, focus and an action in progress independently pause expiry; a real nine-second recovery test covers pointer leave while focus remains.                                                                    |
| Labeled navigation/panel/example containers and palette group IDs have invalid semantics | Accessible names can be ignored or refer to nonexistent groups                                              | Explicit group roles and whitespace-free IDs, checked with direct DOM ID-reference assertions.                                                                                                                   |
| First-publication username dialog has no accessible dialog name                          | Screen-reader users lack context on entering it                                                             | Dialog and fields explicitly named.                                                                                                                                                                              |

The baseline real-desktop reproduction failed at Shift+Tab escaping Add Crux (`/tmp/v1-a11y-baseline.log`). The first expanded run passed automated scanning, single-dialog focus, model selection and invalid-field recovery, but failed the nested dialog's initial focus (`/tmp/v1-a11y-expanded.log`). Neither run is reported as wholly passing. The later acceptance run reproduced the expiring keyboard-focused Undo (`/tmp/v1-a11y-acceptance.log`, seven passed/one failed), which is now fixed.

## Repeatable checks

- Build the renderer with `npm run verify` in `app/`.
- Run `npm run verify` in `app/electron/`.
- Run `npx playwright test e2e/accessibility.spec.ts` in `app/electron/`. The spec also belongs to the normal desktop gate.
- Run `npx playwright test --project=gate` to exercise the surrounding workflows.
- Run the existing public-site suite for shared UI changes: `npm run test:web`.

The scanner uses axe's WCAG A/AA rule tags and asserts zero reported violations, plus a minimum number of passing checks so an empty scan cannot silently pass. It saves full violations and incomplete results alongside each test. Separate behavior tests cover things a static scan missed: actual keyboard boundaries, stacking, initial focus, selected model, error recovery, destructive-action safety, keyboard-safe Undo and 200% zoom. Direct checks also validate visible ARIA ID references and reject prohibited-attribute review findings.

## Limits

Automated scanning is not a WCAG conformance declaration. Canvas/animated backgrounds can make contrast inconclusive; incomplete results need visual/assistive-technology review. This run uses the default Mood. All 65 Moods, every upstream editor command, screen-reader speech with VoiceOver/NVDA, high-contrast OS modes and real installed Windows/Linux keyboard/assistive-technology interaction are not established by these tests. The Release Expedition remains the manual acceptance ledger.

Final targeted acceptance: **8/8 desktop tests**, **18 scanned states with zero reported violations**, plus direct ARIA-reference assertions (`/tmp/v1-a11y-final-desktop.log`). App verify passes **1,670 tests/264 files, 18 skips**, typecheck/lint/build (`/tmp/v1-a11y-final-verify.log`); Electron verify passes **77 tests, one skip** (`/tmp/v1-a11y-electron-verify.log`). Full desktop/public regression and packaged acceptance are recorded below when complete.

`verification.json` records scan summaries and incomplete-review counts. `zoomed.png`, `zoomed-creation.png` and `zoomed-bounds.json` show the actual desktop at 200% zoom. Electron native `webContents.capturePage()` is used because Playwright page screenshots crop incorrectly at non-default Electron zoom; the test independently asserts dialog bounds fit the viewport.

Surrounding desktop regression (`/tmp/v1-a11y-full-desktop.log`): **72 passed, one screen-sharing request timed out waiting for Chromium to reject it**. The unchanged permission spec passed twice in isolation (3.4s/3.3s); its source was not modified. The original full run remains a failed run, with timing cause unproven. Its trace is retained at `/tmp/v1-a11y-permission-failure/`. The adjacent source-picker ownership/consent case passed in the full run and both isolated runs.

Additional usability acceptance passes: keyboard-only create/edit/escape/focus return, Settings at125% in a1000px window without clipped controls, narrow account menu, remote loading/empty/error outcomes, and model-menu placement at short window heights. The existing Settings test used a retired `.mosaic-window` selector; it now selects the actual pane body and checks all four Settings groups at the original narrow width. Evidence: `/tmp/v1-a11y-regression-focus-final.log` (**5/5**), model placement in `/tmp/v1-a11y-regression-focus.log` (the earlier batch had the stale Settings assertion; it was not all green).

Public-browser acceptance: **16/16** public-site journeys plus **1/1** real SQLite worker recovery integration (`/tmp/v1-a11y-web.log`). These include phone layouts, docs/search/journal, Explore package links, signup/return and public-profile behavior using the HTTP fixture.
