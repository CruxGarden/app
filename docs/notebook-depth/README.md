# Native notebook analysis workflow

JupyterLite depth extension, 2026-09-14. Evidence is generated by `electron/e2e/jupyterlite-depth.spec.ts` against the real desktop app using the scripted model and disposable Gardens. External HTTP is blocked during analysis and re-execution. This is integration evidence, not a live-model capability evaluation.

The workflow uploads a small CSV in the native file browser, creates a Python notebook, runs a deliberately wrong column reference, inspects the native error, corrects the source and re-runs to produce a mean of 4 cm and a bar chart. A person adds a Markdown lab note; the collaborator revises and organizes the notebook while preserving that note. Native cell Undo/Redo, PNG and `.ipynb` outputs, restart and complete export/import with the original Project Folder moved away are covered. The imported notebook runs in a fresh kernel with the saved CSV and remains manually editable.

- `seedling-heights.png`: native Matplotlib PNG output, values 2, 4 and 6 cm.
- `native-analysis.png`: native notebook, person-authored note, code, chart and findings.
- `portable-analysis.png`: imported native notebook after fresh execution and another manual edit.

The final extended journey passed in approximately 1.2 minutes, including native text Undo/Redo that reverses the agent's change while preserving the person's preceding note. The full app gate passed all bundled checks, 1,086 host tests across 182 files and the production build (1m 38s). Electron verify passed. The existing notebook conflict/reload/download/restart regression passed in 47.4 seconds. Source/native validation and host persistence/packaging checks pass. Final screenshots and the exported plot were visually inspected.

The final test explicitly waits for the new execution result after import: the imported conversation already contains an earlier identical closing sentence, and imported Collaboration is persisted in history records rather than inline root metadata. The initial wait/lookup mistakes were corrected in the test; no product change was needed for those failures.

The updated runtime ships with new notebook Cruxes; existing Project Folders are not automatically upgraded.

Limits: active-notebook operations; bounded source and output inspection; selected-cell execution with a 60-second timeout; native file-browser upload for datasets. Kernel state and execution side effects are not cell-Undo history. Saved code outputs can be stale until re-executed. No arbitrary kernel/package-management, interactive stdin or automatic host-Artifact mount is added.
