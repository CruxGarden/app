# Large Working Copy performance tests

These opt-in tests exercise 1,000, 10,000 and 50,000 Markdown Artifacts using
production storage, Growth and archive code. Every note has unique content,
defaults to 1 KiB, and lives in a nested hierarchy: shelves of 1,000 notes,
chapters of 100, with an additional four directory levels for every tenth note.
Three Growth snapshots capture two rounds of changes to 1% of the notes.

The [September 10 baseline](baselines/2026-09-10/README.md) records passing
storage checks and failing desktop load cases. The load suite currently exposes
real failures; it is not an all-green performance claim.

The tests assert correctness; timings are observations, not portable speed
guarantees. The desktop's configurable phase deadline is a coarse stall guard,
not a UI latency target. A timeout is a failing test, never silently skipped.
These checks require no AI key, network service or changes to your real garden.

## Run

Use each project's `.nvmrc`. Run performance suites sequentially on an otherwise
quiet machine; ordinary verification/builds should finish before measurements.

```sh
# In app/: validate test code, then measure the service layer and create fixtures.
npm run test:performance:check
npm run test:performance

# In app/electron/: build current production code, then measure native desktop.
npm run build:all
CRUX_PERF_SEED=archive npm run test:performance

# Separately exercise a burst of external writes into new nested folders.
CRUX_PERF_SEED=burst npm run test:performance
```

`archive` imports the unversioned fixtures generated by the service benchmark.
It allows browse/snapshot/edit/export/fresh-import measurements even when a
watcher problem prevents the external-write test from reaching those operations.
`burst` (the desktop default) first proves the watcher is receiving a sentinel
file, then writes the entire hierarchy externally and requires every note to be
indexed. It also checks that node_modules, .git and dist content is excluded.
Both modes check all current and historical path/fingerprint pairs and sample
actual restored files in a second, completely fresh garden.

Configure either suite with:

| Variable                     | Default            | Purpose                                                |
| ---------------------------- | ------------------ | ------------------------------------------------------ |
| `CRUX_PERF_FILES`            | `1000,10000,50000` | Comma-separated positive file counts                   |
| `CRUX_PERF_BYTES`            | `1024`             | Bytes per note (minimum 128)                           |
| `CRUX_PERF_SNAPSHOTS`        | `3`                | Snapshot count; e.g. 100 for a long-history experiment |
| `CRUX_PERF_PHASE_TIMEOUT_MS` | `180000`           | Desktop phase deadline                                 |
| `CRUX_PERF_SEED`             | `burst`            | Desktop setup: external burst or generated archive     |

Use matching file counts and sizes when generating and importing archive fixtures.
For a quick run, set `CRUX_PERF_FILES=1000` for both commands. Playwright's
`--repeat-each=3` records separate desktop repetitions. Long-history experiments
may also need Playwright's `--timeout` increased from the 30-minute case limit.

## Measurements and their limits

- **Service layer:** real SQL through the existing sql.js test client, with an
  in-memory Blob Store. Measures creating/loading Artifacts, building the folder
  tree, snapshot file records, edits, archive export and import into a replacement
  database and Blob Store. Records database/archive bytes and process memory
  before/after each operation. It does not model filesystem or Electron IPC cost,
  render the tree, or run the complete Growth UI/thumbnail lifecycle.
- **Desktop:** real Electron, native SQLite, Blob Store, Project Folders, watcher
  and built React interface. Measures folder expansion/opening a note, full UI
  snapshots, 1% external edits, export and fresh-garden import. Checks viewport
  virtualization. Polls lightweight counts during ingestion rather than repeatedly
  transferring the entire file list. Sampled memory sums Electron process working
  sets once per second and at operation boundaries: shared pages can be counted
  twice, short peaks can be missed, and this is not a leak measurement. Test-runner
  memory used to transport/inspect archives is excluded from this figure.
- Both keep unchanged content deduplicated and verify historical content survives.
  Fixture generation and archive inspection are outside measured export timings.
  Import timing includes reaching the workspace and checking its current file list.
- No Task merge, restart recovery, large binary media, filesystem search, or AI
  context benchmark is implied by these results. The workload is small text files.

Generated service results and seed archives live in `performance/.results/`.
Desktop reports, failure screenshots and output archives live in
`electron/performance/.results/`; `performance.json` is attached to each test.
Copy reports elsewhere before another desktop run, because Playwright clears its
output directory. Test gardens use the shared launch helper's temporary directories.
Both result directories are ignored by Git. `npm run verify` checks performance
test types/lint but does not run hardware-dependent load tests.
